# Поставка и границы расширений, версия 0.7.0

Седьмой, последний этап исходного плана. Математическая модель не расширена.
Источники PMG v5 сверены на ревизии `4bea8e6e52c1299510dab05e5d96dbe6ea79d796`;
PythonExamples остаются на том же проверенном снимке. Результаты испытаний:
[STAGE_SEVEN_VALIDATION.md](STAGE_SEVEN_VALIDATION.md).

## Границы модулей

| Область | Ответственность и зависимости |
| --- | --- |
| `core` | Контексты, exact/numeric сети, метрика, редукции, формальная алгебра; NumPy, SymPy, общие механизмы `_core` |
| `_core.scalars`, `_core.topology` | Общие рациональные операции и обход компонент для нового и старого API |
| `adapters.records` | Версионированная запись вычисления и ограниченный диспетчер; зависит только от ядра и стандартной библиотеки |
| `adapters.networkx` | Обмен строгими сетями с NetworkX; явный полный порядок вершин, точные веса, изоляты, суммирование параллельных рёбер |
| `matrix.networkx`, `matrix.pandas` | Сохранённые адаптеры прежнего матричного интерфейса |
| `matrix`, `objects`, `combinations`, прочие `_core` | Совместимость; здесь остаются прежние сферические, спектральные, направленные и другие исследовательские операции |
| `tests/reference` | Независимые конечные эталоны; не часть публичного API |

Импорт `polyform_algebra.core` не загружает исследовательские классы, адаптеры,
NetworkX, pandas или SciPy. Старые импорты из `polyform_algebra` загружаются по запросу
и возвращают те же классы; `from polyform_algebra import *` сохранён.
Вычислительное ядро не зависит от тематических расширений.

Не все старые численные решатели заменены строгими алгоритмами: у прежнего
интерфейса собственные соглашения о допусках, представлениях матриц и направленных
сетях. Они сохранены ради совместимости; расхождения областей допустимости не
скрываются автоматическим переходом. Общая рациональная арифметика и топология
переиспользуются, а совпадающие области проверяются регрессиями обоих API.
Физический перенос тематических классов в новый каталог не нужен для этой границы.
Новые тематические модули должны зависеть от `core`, обратные импорты запрещены.

## Установка и проверяемые среды

Обычная установка и `[dev]` сохраняют NetworkX в обязательных зависимостях,
чтобы прежние примеры продолжили работать. `.[tables]` добавляет pandas;
сам pandas по-прежнему импортируется только внутри табличного адаптера.
Изменение `requires-python>=3.8` не выполнялось. Это историческая нижняя граница
metadata, а не заявление о проверке всех версий Python: матрица этого этапа —
Python 3.12/3.13, Windows/Linux. Старые версии не входят в подтверждённую матрицу.

Прямые версии зависимостей закреплены в `constraints/py312.txt` и `py313.txt`.
Полные списки фактически установленных транзитивных зависимостей сохраняются
в JSON-отчётах проверок. Metadata остаётся только в `pyproject.toml`.

`tools/check_distribution.py` создаёт временное окружение вне checkout,
устанавливает wheel, копирует тесты и примеры, проверяет источник импорта,
версию, а затем запускает pytest. Режим `--core-only` устанавливает только
NumPy/SymPy/pytest и wheel с `--no-deps`: отсутствие NetworkX/pandas/SciPy
проверяется фактически. Это проверка независимости ядра, а не новый способ
обычной установки: `pip check` такого минимального окружения ожидаемо отметил бы
сохранённую зависимость совместимости NetworkX. Полный режим выполняет `pip check`.

GitHub Actions запускает обе проверки на каждой паре Python/ОС, всего 8 заданий.
Wheel собирается через sdist; тестирование выполняется вне исходной папки.
Отчёты содержат версии, путь установленного пакета и XML результатов.
Настройка следует [официальной документации GitHub](https://docs.github.com/en/actions/tutorials/build-and-test-code/python).
Публикация в PyPI и сервер ИИ-агента в этот этап не входят.

## Запись вычисления

`adapters.records.execute_network(operation, vertices, edges, *, arithmetic, policy, arguments)`
принимает Python-данные, вызывает только операции из `OPERATIONS` и возвращает
JSON-совместимый словарь. Это локальный адаптер, не сервер и не парсер произвольных
JSON-запросов. Поддержаны `laplacian`, `green`, `resistance`, `spanning_tree_weight`,
`dirichlet`, `kron_reduce`, `contract`, `induced_subgraph`, `simplex_volume_squared`.
Аргументы операций имеют имена ядра: `pairs`, `boundary`, `keep`, `partition`, `vertices`.

`calculation_record(calculation, input_data=...)` экспортирует другие результаты
ядра, включая формальные, без расширения реестра исполняемых операций.
Вызывающая сторона отвечает за соответствие переданных входов результату;
диспетчер `execute_network` обеспечивает это соответствие сам.
`encode` и `canonical_json` доступны отдельно.

Поля: `schema_version`, `operation`, `core_version`, `definition_revision`,
`definition_url`, `arithmetic`, `input`, `input_digest`, `status`, `value`,
`diagnostics`, `error`. Версия схемы — `1`. Успех имеет статус `exact` или
`approximate`, ошибка — `error`, пустое значение и стабильный код исключения.
Несвязное сопротивление — успешное типизированное `positive_infinity`.

Рациональные числа кодируются `{type: rational, numerator: строка, denominator: строка}`,
знаменатель положительный; целые, строки, tuple и float различаются по типу.
NaN, отрицательная бесконечность и произвольные Python-объекты отвергаются.
`eval`, pickle и динамический поиск вызываемой функции не используются.
Сериализация не даёт права исполнять или автоматически восстанавливать классы.

SHA-256 строится по каноническому JSON закодированного запроса, включая операцию,
режим и эффективную политику точности. Порядок вершин, рёбер и элементов отображений
сохраняется: порядок групп стягивания определяет порядок выходных вершин.
Поэтому математически эквивалентные, но по-разному записанные запросы могут иметь
разные хеши. UUID созданных диспетчером контекстов в хеш не входят.
При не-кодируемом входе `input` и `input_digest` равны null; данные не заменяются
ненадёжной строкой repr. Неизвестная операция даёт `UNSUPPORTED_OPERATION`.

В диагностике сохраняются режим, политика, проверки и невязки. Запись не объявляет
математическое утверждение доказанным. Указатель на Core specification задаёт базовые
определения; конкретные источники операций перечислены в контрактах ядра и корпусе.
Пример запуска: `python -m examples.computation_record`.

## Уточнение структуры в 0.8.0

Реализации `matrix.pandas` и `matrix.networkx` перенесены в `adapters.pandas`
и `adapters.matrix_networkx`. Старые пути сохранены как совместимые импорты.
Строгий `adapters.networkx` версии 0.7.0 сохранён без изменений. Внешний обмен
выделен в `connectors`, пока с абстрактными контрактами DataSource/ResultSink.
[Новый контракт](ADAPTERS_AND_CONNECTORS.md), [прикладной план](PMG_APPLIED_INTEGRATION_PLAN.md).
