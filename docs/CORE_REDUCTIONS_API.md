# Преобразования сетей: контракт этапа 4

Версия 0.5.0. Все функции импортируются из `polyform_algebra.core` и возвращают
`Calculation(value, diagnostics)`. Реализованы D01–D05 ТЗ для конечных
неориентированных сетей с неотрицательными рациональными (`exact`) или
конечными вещественными (`numeric`) проводимостями. Новых зависимостей нет:
точное решение использует SymPy, численное — NumPy.

## Функции и результаты

| Функция | `value` | Смысл |
| --- | --- | --- |
| `dirichlet(net, boundary)` | `DirichletResult(P,I,B,H)` | `B=-solve(L_II,L_IP)`; строки `H` на P — единичные, на I — строки B |
| `extend(result, boundary_values)` | `Coordinates` в исходном контексте | Значения `H g`; также доступно `result.extend(values)` |
| `kron_reduce(net, keep)` | `ReductionResult(network,H,P,I)` | Сеть с лапласианом `HᵀLH`, сохраняющая сопротивления между оставленными вершинами |
| `contract(net, partition)` | `ContractionResult(network,S)` | Отождествление групп: `L_new=SᵀLS`; S переносит новые значения на исходные вершины |
| `induced_subgraph(net, keep)` | `Network` | Только связи, оба конца которых сохранены; степени пересчитываются |

`boundary` и `keep` — упорядоченные последовательности уникальных меток.
P сохраняет переданный порядок; I — порядок остальных вершин исходной сети.
`partition` — отображение `new_label -> ordered_members`: непустые группы
покрывают все исходные вершины ровно один раз. Связность группы не требуется.
Порядок новых вершин задаётся порядком ключей отображения.

Матрицы B, H, S имеют `representation='operator'` и явные контексты обеих осей.
В частности, H имеет размер `|V| × |P|`, B — `|I| × |P|`, S — `|V| × |groups|`.
`H.rows` и `S.rows` — исходный контекст. Контексты P, I и результирующих сетей
новые: это другие пространства, а не перестановка исходного.
У редукции `network.context is H.columns`, у стягивания — `network.context is S.columns`.
Результаты неизменяемы; `to_numpy()` возвращает независимую копию.
`to_numeric()` поддерживает эти матрицы операторов; автоматического преобразования
целого составного результата нет. `reorder()` по-прежнему предназначен для
одного контекста и квадратных матриц с совпадающими осями.

Для `extend` передаётся именно `dirichlet(...).value`. Данные — отображение
с полным и только полным набором меток P либо `Coordinates(result.H.columns, ...)`.
Новый независимо созданный контекст с такими же метками не считается тем же
пространством. Обычный список без контекста не принимается. В точном режиме
дроби сохраняются; `float`, в том числе `0.0`, отвергается.

## Условия и крайние случаи

- Для Дирихле и Крона каждая компонента должна содержать выделенную вершину.
  Иначе `NonuniqueProblem` с кодом `NONUNIQUE_PROBLEM`; `parameters` содержит
  компоненты без выделенных вершин. Псевдообратная не применяется.
- Пустая сеть для этих двух операций — `DOMAIN_ERROR`; пустой выбор на непустой
  сети, повторные/неизвестные метки или неверное разбиение — `INVALID_INPUT`.
- Если выбраны все вершины, B имеет размер `0 × |V|`, H — матрица перестановки.
  Если в компоненте выбрана одна вершина, продолжение постоянно, отклик нулевой.
- Изоляты должны входить в P. Подграф с пустым выбором допустим. Стягивание
  пустой сети допускает только пустое разбиение; S имеет размер `0 × 0`.
- Между разными компонентами B не создаёт влияния, а Крон — новых связей.
  Бесконечные межкомпонентные сопротивления сохраняют смысл этапа 3.

## Численная политика

Внутренний блок решается отдельно для каждой компоненты после масштабирования.
Проверяются положительность спектра, обусловленность, относительная невязка,
неотрицательность B, единичные суммы строк и соответствие нулей B топологии.
Бюджет включает `NumericPolicy.rtol` и нижнюю границу погрешности float64.
Слишком плохо обусловленная система получает `NUMERICAL_UNRESOLVED`, даже
если математически решение единственно. Это ограничение численного метода.
`diagnostics.numerical` содержит `SolveCheck`: внутренние метки, масштаб,
ранг, обусловленность и невязку нормированной системы. У задачи без внутренних
вершин список пуст. Точные ответы не содержат численных оценок погрешности.

Крон вычисляет положительные наведённые проводимости
`c_pq + sum_x c_px B_xq`, избегая вычитания близких диагональных вкладов.
Проводимости из двух направлений должны совпадать в пределах `rtol` и
`conductance_atol`. Разрешённое усреднение фиксируется в `diagnostics.corrections`
как `('symmetric conductance', p, q, forward, backward, mean)`.
Степени строятся заново; полный отклик `LH` сверяется с результирующим
лапласианом по компонентам. Малые положительные связи не отбрасываются.
Исчезновение положительного влияния/произведения и переполнение вызывают
ошибку неопределённости, а не превращаются в отсутствие связи.

Стягивание суммирует только межгрупповые проводимости (в numeric через `fsum`).
Это сохраняет, например, связь величины 1 между группами с внутренними связями
`1e100`, где прямое матричное вычисление `SᵀLS` может потерять результат.

## Эталоны и совместимость

Для пути a–x–y–b с проводимостями 2,1,3:

- P=(a,b), B=((8/11,3/11),(2/11,9/11)); значения (0,11) продолжаются в (0,3,9,11).
- Энергия равна 66. Крон даёт связь 6/11 и сопротивление 11/6.
- Подграф на (a,b) не имеет связей; стягивание (a,x),(y,b) даёт связь 1.
- Исключение центра единичной трёхлучевой звезды даёт треугольник со связями 1/3
  и попарными сопротивлениями 2.

Пример: `python -m examples.core_reductions`. Проверки —
`tests/test_core_reductions.py`; прежние методы `Laplacian.dirichlet`,
`eliminate`, `contract`, `induced_subgraph` и их форматы результатов сохранены.
Общий математический алгоритм переиспользован, но старые численные допуски
и классы не заменены новым контрактом. Унификация внутренних механизмов
остаётся задачей этапа 7 и требует отдельной проверки совместимости.
Публичные PythonExamples продолжают проверяться по зафиксированным блокам:
[описание проверки](PUBLIC_PYTHONEXAMPLES.md).
