## Подготовка и запуск

Из корня проекта после установки `python -m pip install -e ".[dev]"`:


В коде расчёты выполняются с числами с плавающей точкой. Дроби в таблицах ниже
задают точные ожидаемые значения; тесты сравнивают результаты с допуском.

## Соответствие обозначений

| PMG | Python | Значение |
| --- | --- | --- |
| a₁, a₂, a₃ | `a, b, c = Point.create_list(["1", "2", "3"])` | Формальные вершины |
| (12) | `b - a` | Аффинный вектор |
| [(12)]² | `quForm([(a, b)])` | Квадратичная форма границы |
| e | `Polyform.one()` | Единица алгебры форм |
| L | `f12 + f13 + f23` | Лапласиан единичного треугольника |
| M = exp L | `laplacian.exp()` | Метрическая полиформа |
| τ(M) | `metric.potential(quForm.one())` | Остовной коэффициент |
| R₁₂ | `metric.norm(f12)` | Нормированный потенциал квадратичной формы |
| (12)·(13) | `metric.norm((b-a) @ (c-a))` | Численное скалярное произведение |

`@` сначала строит скалярную полиформу; `norm` вычисляет её численную оценку.
`potential(f13)` — вес соответствующих разделяющих 2-лесов, а не электрический
потенциал отдельной вершины. Экспонента здесь использует произведение форм,
а не матричное произведение.

## Заметка 6: одна связь

Исполняемый файл: [note06_single_edge.py](../examples/introductory/note06_single_edge.py).

Исходные проводимости треугольника равны единице. Увеличиваем проводимость 12
на δ = 1, до значения 2. Поскольку f₁₂² = 0, достаточно обновить экспоненту:

```python
updated = metric * (Polyform.one() + delta * f12)
```

Независимо пересчитываем `(laplacian + delta*f12).exp()` и проверяем
эквивалентность двух полиформ. Это позволяет использовать уже построенную
метрику при локальном изменении сети.

| Величина | До изменения | После изменения |
| --- | ---: | ---: |
| τ | 3 | 5 |
| R₁₂ | 2/3 | 2/5 |
| R₁₃ | 2/3 | 3/5 |
| R₂₃ | 2/3 | 3/5 |
| Вероятность ребра 12 в остове | 2/3 | 4/5 |
| Вес 2-лесов, разделяющих 1 и 3 | 2 | 3 |

Вероятность ребра вычисляется как c₁₂R₁₂: после усиления необходимо использовать
новую проводимость 2. Прирост лесного веса равен 1.

Функция `calculate()` возвращает эти значения и сравнение с формулами заметки:
τ′ = τ(1 + δR₁₂), R′₁₃ = R₁₃ − δg²/(1 + δR₁₂), где g = (12)·(13) = 1/3.

## Заметка 7: две связи

Исполняемый файл: [note07_two_edges.py](../examples/introductory/note07_two_edges.py).

Увеличиваем проводимости 12 и 13 с 1 до 2. Используем два множителя:

```python
updated = metric * (Polyform.one() + f12) * (Polyform.one() + f13)
```

Сравниваем результат с `(laplacian + f12 + f13).exp()` и повторяем расчёт
в обратном порядке факторов. Ориентации выбранных векторов: 1→2 и 1→3;
измеряемого вектора: 2→3.

| Величина | Результат |
| --- | --- |
| Матрица Грама выбранных связей | `[[2/3, 1/3], [1/3, 2/3]]` |
| Вектор взаимодействий с (23) | `[-1/3, 1/3]` |
| τ после первого усиления | 5 |
| R₁₃ после первого усиления | 3/5 |
| τ после обоих усилений | 8 |
| R₂₃ после обоих усилений | 1/2 |
| det(I + G) | 8/3 |
| Коэффициент при δ₁δ₂ в изменении τ | 1 |
| Вероятность совместного включения рёбер 12 и 13 в исходный остов | 1/3 |

Коэффициент совместного действия вычисляется прямо в алгебре:
`metric.potential(f12*f13)`. Он согласуется с τ·det(G). Это иллюстрирует,
почему совместную вариацию нельзя заменить произведением отдельных первых
производных: существенен смешанный член.

Последовательная формула использует обновлённую метрику после первого шага:
5·(1 + 3/5) = 8. В примере также проверяются определительная формула для τ
и формула сопротивления через `numpy.linalg.solve(I+G, q)`.

## Проверки и границы примеров

[Тесты](../tests/introductory/test_triangle_variations.py) проверяют точные числа
из заметок, ориентационные знаки, эквивалентность факторного обновления
пересчёту экспоненты и независимый матричный расчёт. В последнем лапласиан
строится непосредственно из проводимостей: τ получается из минора, а R₂₃ —
из решения сети с единичным током и заземлённой вершиной 3.

Примеры демонстрируют конкретное усиление связей. Они не вводят общий API
вариаций, не обрабатывают произвольное удаление мостов и не заменяют проверки
допустимости сети. Публичная алгебра остаётся квадратичной.

Для будущей публикации в PMG удобно сохранить эту структуру: исходная задача,
соответствие обозначений коду, запуск, ожидаемые результаты и независимая
проверка. Полный код лучше хранить в Python-репозитории, а в заметках приводить
ключевые строки и ссылку на проверенную ревизию, чтобы реализации не расходились.
