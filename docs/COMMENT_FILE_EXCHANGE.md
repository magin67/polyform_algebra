# Файловый обмен «сотрудники — документы — комментарии», 0.9.0

Дата: 9 ноября 2026 года. Схема данных 1. Реализован файловый обмен, без подключения
к живой базе 1С. Численные и формальные операции PMG не менялись.

## Границы этапа

`applications.comments` проверяет прикладные данные и их идентичность.
`connectors.files` читает снимок и публикует результаты; не определяет веса графа.
`connectors` по-прежнему экспортирует DataSource/ResultSink без загрузки математики.
Файловые классы импортируются явно из `connectors.files`.

Первая версия принимает полный снимок за полуоткрытый период [start,end).
Время — ISO 8601 с секундами и обязательным смещением UTC (или Z), до 6 знаков
долей секунды. Сравниваются моменты времени, а не строки. Именованные часовые зоны
не интерпретируются. Каждый комментарий — одно событие. Агрегированные количества,
редактирования, удаления, дельты и произвольные веса пока не поддерживаются.
Повторные ID комментариев отклоняются, включая дословные повторы: производитель
должен устранить дубли до выгрузки. Неполный снимок не принимается.

## Входной JSON

См. готовый синтетический файл `examples/data/comments_snapshot.json`.
UTF-8, допустим BOM; повторяющиеся JSON-ключи, NaN/Infinity и неизвестные поля запрещены.

| Поле | Тип / смысл |
| --- | --- |
| schema_version | Строка "1" |
| kind | "comment_snapshot" |
| source_system | Непустой постоянный ID информационной базы/источника |
| snapshot_id | Непустой ID выгрузки |
| period | Объект start/end, start < end |
| exported_at | Момент выгрузки, не раньше конца периода |
| complete | Только true; подтверждается производителем выгрузки |
| employees | Массив объектов {id, label} |
| documents | Массив объектов {id, label} |
| comments | Массив объектов {id, employee_id, document_id, occurred_at} |
| filters | Необязательный JSON-объект с условиями отбора, входит в хеш |

Все идентификаторы и подписи — непустые строки. UUID 1С подходит, но не обязателен:
строка "001" сохраняется как "001". Идентичность определяется источником, таблицей
и ID: сотрудник "001" и документ "001" — разные объекты. Одинаковые подписи разрешены.
В каждой таблице ID уникальны; ссылки комментариев обязаны разрешаться в справочниках.
Сотрудники и документы без событий сохраняются. Пустой полный снимок допустим.
Текст комментария для этого сценария не требуется.

Флаг complete не позволяет библиотеке доказать полноту относительно базы:
это обязанность выгрузки 1С. Рекомендуется выгружать справочники и события из одного
согласованного среза. Пользовательские filters описывают уже выполненный отбор;
файловый коннектор сам не отбирает и не объединяет данные.

## Чтение

```python
from polyform_algebra.connectors.files import CommentSnapshotFileSource
source = CommentSnapshotFileSource("comments.json")
snapshot = source.read_snapshot({})
# Или проверка ожидаемой выгрузки:
snapshot = source.read_snapshot({"snapshot_id": "comments-2026-10"})
```

Иные ключи query отклоняются. Возвращается независимая проверенная копия данных.
Отсутствующий файл даёт FileNotFoundError; ошибка содержимого — DataContractError.
Лимит по умолчанию 16 MiB, настраивается max_bytes; превышение не усекaет файл.

`snapshot_digest(snapshot)` — SHA-256 канонического UTF-8 JSON: ключи объектов
сортируются, порядок массивов сохраняется. Хеш учитывает весь снимок, включая подписи,
период, время выгрузки и filters. Новая запись того же содержания с другим форматированием
имеет тот же хеш; перестановка строк считается другим представлением снимка.

## Выходной JSON

Готовый пример: `examples/data/comments_result.json`, соответствующий входному примеру.

Обязательные поля:

- schema_version="1", kind="comment_results", status="completed";
- run_id — непустой ID расчёта, уникальный в пределах source_system;
- source_system, snapshot_id и snapshot_digest исходного снимка;
- model={id, version, parameters}, где parameters — JSON-объект;
- library_version — версия вычислителя; created_at — время не раньше выгрузки;
- metrics, edges, messages — массивы, допускающие пустые значения.

Строка metrics: employee_id, metric, status, value; необязательны строковые
component, normalization, reason. Пара (employee_id, metric) уникальна, сотрудник
должен существовать в снимке. Набор обязательных показателей определяется сценарием,
а не транспортом; completed означает завершение заявленного расчёта, не проверку
всех мыслимых показателей. Пропущенная строка не означает нулевой показатель.

| status | value |
| --- | --- |
| exact | {"type":"rational","numerator":"2","denominator":"1"} или типизированная положительная бесконечность |
| approximate | {"type":"number","value":0.25}, рациональное представление приближённого значения или типизированная бесконечность |
| undefined | null и обязательный непустой reason |

Рациональные числитель/знаменатель — десятичные целые строки; знаменатель положительный.
`{"type":"positive_infinity"}` отличается от undefined и нуля. Статус точности
задаёт вычислитель: валидатор не доказывает правильность числа или заявленной точности.

Строка edges: source_id, target_id, weight. Пока это неориентированные связи сотрудников;
неизвестные вершины, петли и повтор пары в любом порядке запрещены. weight — положительное
конечное значение типа rational или number. messages — массив непустых строк диагностики.
Для голосования потребуется отдельный контракт, а не изменение смысла этих рёбер.

## Публикация и повторная передача

```python
from polyform_algebra.connectors.files import CommentResultFileSink, read_comment_result
sink = CommentResultFileSink("results", snapshot)
receipt = sink.publish(result, idempotency_key=result["run_id"])
restored = read_comment_result(receipt["path"], snapshot)
```

В каталог записывается непосредственно JSON результата; внешняя оболочка не требуется.
Файл называется хешем пары (source_system, run_id), поэтому ID не превращается в путь.
Подтверждение содержит status (created/existing), run_id, абсолютный path и sha256
канонического результата без конечного перевода строки. Это не хеш сырых байтов файла.

idempotency_key обязан совпадать с run_id. Равный повтор возвращает existing; иной
результат с тем же ключом — PublicationConflict. Новый расчёт требует нового run_id.
Изменение версии модели, библиотеки или времени также меняет результат, поэтому
повторять следует исходный пакет, а не генерировать его заново.

Файл сначала полностью записывается и синхронизируется во временном файле того же
каталога, затем публикуется атомарной жёсткой ссылкой без замены существующего имени.
Конкурентные отправки не перезаписывают друг друга. При обычной ошибке временный файл
удаляется; после аварийного завершения процесса может остаться .pmg-*.tmp, который
не является результатом и не должен импортироваться в 1С. Потребитель читает только
конечные *.json. Гарантии долговечности после сбоя питания зависят от файловой системы.

Требуется файловая система с поддержкой жёстких ссылок (проверено на Windows/Linux CI).
Если файловая система или права не позволяют публикацию, операция завершается OSError;
небезопасного запасного варианта с частичной записью нет. Каталог должен находиться
под управлением интеграции; конкурентная публикация поддержана, внешняя замена или
удаление файлов после публикации не блокируется этим коннектором.

## Сторона 1С и следующий шаг

1. Сформировать согласованную выгрузку по указанной схеме и сохранить UTF-8 JSON.
2. Передать файл расчётному процессу, получить JSON результата и проверить снимок/версию.
3. Найти объекты по source_system + тип + ID, показать metrics и edges.
4. Хранить ключ расчёта при импорте: повтор не создаёт повторных записей в регистрах 1С.

Python-коннектор обеспечивает повторяемую публикацию файла; идемпотентность импорта
в 1С должен отдельно обеспечить её обработчик. Такой обработчик в данном этапе не создан.
Источник не изменяется, исходные комментарии не редактируются.

`python -m examples.comment_file_exchange` демонстрирует полный файловый круг
на вымышленных данных: активность сотрудников 2,1,0 и безопасный повтор.
Это пример счётчика, не реализация прикладного графового анализа. Следующий этап —
события → матрица участия → редуцированный граф → показатели, с использованием
этих же контрактов.
