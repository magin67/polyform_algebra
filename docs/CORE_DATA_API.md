# Контексты и точная арифметика: второй этап

Версия 0.3.0. Реализованы C01/C04/C05 и общие структуры данных второго этапа.
Математический источник — спецификация PMG v5, редакция 27: пространство,
аффинный вес, суммарные проводимости и внешняя алгебра. Полное ТЗ остаётся
целевым документом; реализация решателей и нового формального API впереди.

Новый интерфейс импортируется из `polyform_algebra.core`. Старые импорты,
классы, матричные методы и их численная политика сохранены.

| Объект / операция | Реализованный контракт |
| --- | --- |
| `Context(labels, arithmetic="exact", epsilon=None)` | Неизменяемый упорядоченный базис с собственной идентичностью. По умолчанию ε=1. Независимые контексты не равны даже при одинаковых метках |
| `coordinates(context, values)` / `Coordinates` | Неизменяемый столбец из списка/кортежа либо полного отображения меток. Сложение, вычитание, рациональное масштабирование и деление. Нуль сохраняет контекст |
| `network(vertices, edges, arithmetic="exact", parallel="sum", policy=None)` | Неориентированная сеть, точное суммирование кратных проводимостей, сохранение изолятов; петли и отрицательные веса запрещены. `parallel="reject"` запрещает также обратные дубликаты и повторные нулевые рёбра |
| `Network(context, edges, policy=None)` | Низкоуровневый проверяемый контейнер уже агрегированных пар; ε=1. Компоненты определяются положительными связями, а не численным порогом |
| `MatrixData(values, rows, columns, representation)` | Неизменяемый контейнер конечных коэффициентов и осей. Проверяет размеры, режимы и сетевые оси; `to_numpy()` возвращает независимую копию |
| `reorder(obj, labels)` | Полная перестановка координат, сети или квадратной матрицы в одном пространстве. Возвращает `Calculation`, данные в `.value` |
| `to_numeric(obj, policy=None)` | Явный перевод сети, координат или матрицы; сохраняет идентичность пространства, меняет режим. Переполнение/исчезновение ненулевого числа запрещены |
| `NumericPolicy` | Неотрицательные конечные `rtol=1e-10`, отдельные `conductance_atol`, `resistance_atol`, `coordinate_atol` (по умолчанию 0). Пока не подключается к старым решателям |
| `Calculation`, `Diagnostics` | Значение и неизменяемая запись операции, версии контракта, режима, политики, статуса и проверок |

Все последовательности передаются списками или кортежами. Множества не
принимаются. Метки — строки, целые Python или рекурсивные кортежи таких меток;
bool и изменяемые элементы запрещены. В точном режиме числа нормализуются в
`Fraction`: поддержаны целые, `Fraction`, `SymPy Integer/Rational` через общий
рациональный числовой протокол. Float, bool, символы и иррациональные числа
отклоняются. Численный режим хранит конечные Python float.

Данные копируются в кортежи. Перестановка сохраняет идентификатор пространства,
но изменяет порядок осей; смешивать координаты до явного согласования порядка
нельзя. Перевод exact→numeric не отождествляет режимы. Старые изменяемые
`Point`/`Basis` не становятся метками строгого контекста автоматически.

Типизированные ошибки этапа: `InvalidInput`, `ContextMismatch`,
`ArithmeticMismatch`, `NumericalUnresolved`, все наследуют `PMGError` и
совместимы с `ValueError`. У них стабильный `.code`, `.parameters` и
`.diagnostics`. Ошибка не возвращается как успешный частичный расчёт.

`MatrixData` пока не удостоверяет, что числа действительно являются
лапласианом или гринианом: математическая проверка представлений относится к
C02/C03 следующего этапа. Маркер бесконечности резистивной матрицы также будет
добавлен вместе с M03; на этом этапе контейнер принимает только конечные числа.
Перестановка прямоугольного Gram по двум независимым осям не входит в C04.
Невязки и обусловленность появятся с решателями; сейчас диагностика сообщает
только выполненные проверки данных и преобразований.

## Рациональные коэффициенты существующей алгебры

Общий механизм скалярной арифметики переиспользуется в `Point`, `Simplex`,
`quForm`, `Polysimplex` и `Polyform`. Целые и рациональные коэффициенты больше
не преобразуются в float и не удаляются по допуску `1e-10`. Деление рациональных
чисел, факториалы конечной экспоненты, поляризация первого грейда и нормированный
потенциал сохраняют точность. Эквивалентность рациональных форм проверяется
без численного допуска; для float прежний допуск остаётся.

Для совместимости метрические `norm` и `scalar_product` на обычных целых/float
входах сохраняют численный результат, пригодный для NumPy. Точный режим этих
старых методов выбирается явными рациональными коэффициентами `Fraction`
или SymPy Rational (они нормализуются в Fraction). В строгих координатах
целые входы сразу становятся рациональными.

Это исправление точности в существующем API, а не новый универсальный CAS.
Старый API допускает смешанные float/рациональные выражения: float переводит
соответствующие коэффициенты в приближённую арифметику. Строгие контексты это
не делают. Экспонента ненулевого скалярного члена в старом API по-прежнему
вычисляется численно. Старые матричные импортеры, смены базиса и спектральные
методы остаются численными. Новый exact-интерфейс форм, его контексты, лимиты
раскрытия и грамматика будут реализованы на пятом этапе.

Пример: `python -m examples.exact_contexts`.
Семейство тестов: `tests/test_core_data.py`, `tests/test_rational_coefficients.py`.

SymPy добавлена как зависимость `>=1.12,<2`; выбирается совместимый с Python
выпуск. Требование Python ≥3.8 на этом этапе не меняется. NumPy/NetworkX и
существующие адаптеры остаются на прежних местах.
