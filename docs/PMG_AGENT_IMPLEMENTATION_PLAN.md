# План создания ИИ-агента публичной библиотеки PMG

Дата: 9 ноября 2026 года. Основание: обсуждение после завершения семи этапов ядра.
Статус: план, без реализации агента. Базовая версия пакета — 0.7.0.

Агент — помощник по чтению и вычислительным исследованиям PMG. Заметки задают
математический смысл, PythonExamples дают воспроизводимые сценарии, ядро выполняет
проверенные операции. Следующий прикладной приоритет пользователя —
[интеграция данных и 1С](PMG_APPLIED_INTEGRATION_PLAN.md); этот план сохраняется
как отдельное направление и не подразумевает немедленную разработку агента.

## 1. Задачи агента

| Задача | Результат |
| --- | --- |
| Объяснение понятий | Определение, условия применимости, пример и ссылки на разделы |
| Навигация | Подбор заметок и маршрута чтения с учётом подготовки пользователя |
| Расчёт сети | Матрицы, сопротивления, потенциалы, остовные коэффициенты, метрика |
| Преобразование графа | Дирихле, Крон, стягивание и подграфы с объяснением различий |
| Формальная алгебра | Поддерживаемые произведения, границы, экспоненты, коэффициенты, сравнение форм |
| PythonExamples | Воспроизведение закреплённого примера и сверка контрольных результатов |
| Исследовательский эксперимент | Явное семейство случаев, поиск контрпримеров, наблюдения и воспроизводимый код |

Первой версии нужны надёжные учебные и вычислительные сценарии. Самостоятельное
исследование новых гипотез добавляется после их проверки. Агент различает доказанное
утверждение, точный расчёт частного случая, численное наблюдение и гипотезу.
Статус относится к отдельному утверждению, а не целиком к заметке.

## 2. Заметки как источники

Создать версионируемый каталог: идентификатор, название, язык, серия, путь,
Git-ревизия, редакция, соответствие переводу, определения, обозначения, условия,
утверждения со статусами, связанные заметки, примеры и вычислительные операции.

Поиск должен извлекать определение вместе с условиями, а не только похожий текст.
Разбиение по смысловым разделам сохраняет формулы, доказательства и ссылки.
Сначала находятся источники, затем проверяется применимость к вопросу.
Содержательные расхождения RU/EN сообщаются явно, а не объединяются молча.

При подготовке плана ветка v5 имела ревизию
`96fb9b4764f943fb7a5e74b847d188bde8191b78`, адаптер ядра закреплён за
`4bea8e6e52c1299510dab05e5d96dbe6ea79d796`. Это не доказательство несовместимости,
но повод отдельно проверить обновления. Различать последнюю доступную редакцию
и редакцию, проверенную с версией ядра; не обновлять вычислительные основания
автоматически вслед за веткой.

## 3. PythonExamples как каталог сценариев

Карточка сценария содержит постановку, данные, соответствие обозначений коду,
ожидаемые значения, независимые проверки и совместимые версии пакета.

Три действия: объяснить существенные шаги; воспроизвести закреплённый код;
адаптировать его к новым данным с повторной проверкой условий. При адаптации
прежние контрольные числа больше не являются эталоном: проверяются свойства
и независимый расчёт новых данных.

Опубликованные примеры старого API сохраняются. Новые могут использовать строгий
интерфейс, но вариант API и версия установки всегда указываются явно.

## 4. Выполнение запроса

Вопрос → источники → математическая постановка → вычисление → проверка → ответ.

1. Установить вершины, веса, порядок меток, выбранные вершины и смысл весов:
   проводимости или сопротивления.
2. Проверить связность, направленность, режим арифметики и представимость форм.
3. Выбрать зарегистрированную функцию или проверенный сценарий.
4. Выполнить расчёт и получить диагностику.
5. Провести подходящую независимую проверку.
6. Выдать результат, объяснение, источники и способ повторения.

Уточнение требуется, если неоднозначность меняет задачу: «убрать вершину» может
означать Крон или индуцированный подграф. Для первой версии достаточно одного
агента с инструментами; несколько взаимодействующих агентов не обязательны.

## 5. Проверка результатов

Точность и способ проверки хранятся отдельно: рациональный ответ не доказывает
общего утверждения. Независимый контроль не должен вызывать тот же алгоритм
повторно под другим именем.

| Результат | Контроль |
| --- | --- |
| Лапласиан | Симметрия, суммы строк, знаки и компоненты |
| Матрица Грина | Соотношения с лапласианом и покомпонентным проектором |
| Сопротивления | Заземлённое решение; на малых графах разделяющие леса |
| Остовной коэффициент | Кофактор; на малых графах перебор деревьев |
| Дирихле | Граничные значения, гармоничность, энергетическое тождество |
| Крон | Сохранение сопротивлений выбранных вершин и энергии |
| Объёмы и формы | Грам, координатное раскрытие, независимый корпус |
| Семейство графов | Явные случаи или воспроизводимый генератор, область перебора, исключения |

Для рациональных входов посильного размера предпочтителен exact. Переход к numeric
явный, с допусками и диагностикой. Неразрешённая слабая связь не объявляется
отсутствующей. Перебор и полное раскрытие ограничиваются ресурсами; частичная
проверка не выдаётся за полную.

## 6. Архитектура и недостающие части

В 0.7.0 есть ядро, независимый корпус, проверки PythonExamples и запись вычисления.
Диспетчер содержит девять сетевых операций, принимает Python-данные и не является
готовым публичным сервисом. См. [контракт поставки](DELIVERY_AND_EXTENSIONS.md).

Добавить каталог и поиск, реестр сценариев, строгие схемы запросов и безопасное
декодирование, инструменты формального ядра, независимые проверки, историю и UI.
К записи вычисления добавить использованные разделы источников, сценарий,
результат контроля и границы вывода. Версию модели и инструкции агента хранить
отдельно от версии математического ядра.

Произвольный исследовательский Python — последующая возможность в отдельном
ограниченном окружении. Код найденной заметки не становится доверенным сценарием
автоматически. Прикладные операции используют общий слой интеграции данных;
доступ к 1С не встраивается непосредственно в математическое ядро или подсказку модели.

## 7. Этапы и приёмка

| Этап | Результат | Критерий готовности |
| --- | --- | --- |
| 1. Источники и задачи | Каталог, термины, статусы, сценарии, контрольные вопросы | Для каждого вопроса известны основания, ожидаемое поведение и ограничения |
| 2. Помощник по библиотеке | Поиск, объяснения, чтение, ссылки | Не смешивает версии, определения, гипотезы и доказательства; сообщает об отсутствии оснований |
| 3. Вычислительный помощник | Сетевые инструменты, схемы, записи | Правильно переводит вопросы в операции; обрабатывает неверные и неоднозначные входы |
| 4. Примеры и алгебра | Воспроизведение, адаптация, формальные инструменты | Сохраняет примеры и явно отклоняет неподдерживаемые формы |
| 5. Проверка и исследования | Контрольные расчёты, ограниченные переборы | Обнаруживает внесённые ошибки и не обобщает конечную проверку до теоремы |
| 6. Публичный пилот | UI, журнал, лимиты, обратная связь | Запросы воспроизводятся; обновления проходят регрессионную проверку |

Первую полезную версию выпускать после этапа 4. Перед публичным пилотом нужен
отдельный корпус испытаний агента: обычные задачи, неоднозначные формулировки,
неверные предпосылки, устаревшие источники и запросы за пределами реализации.
728 тестов библиотеки не проверяют понимание вопроса и качество объяснения агентом.
