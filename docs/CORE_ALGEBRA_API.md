# Формальное ядро PMG: контракт этапа 5

Версия 0.6.0. Реализованы A01–A12 ТЗ в `polyform_algebra.core`.
Формальная арифметика — только точная рациональная. NumPy не используется
для раскрытий; SymPy вычисляет точные определители в метрической оценке.
Новых зависимостей нет.

## Данные и конструкторы

Все объекты неизменяемы, содержат `Context` и сохраняют его у нуля.
Одинаковые метки не отождествляют независимо созданные пространства.
Числа `int`, `Fraction`, `sympy.Integer/Rational` нормализуются в `Fraction`;
`float`, `bool`, бесконечности и общие символы не принимаются.

| Конструктор | Представление |
| --- | --- |
| `exterior(context, coefficients, limits=...)` / `Exterior` | Отображение или последовательность пар `(tuple_of_indices, coefficient)` |
| `simple_term(context, factors=(), coefficient=1, limits=...)` / `SimpleTerm` | Произведение допустимых факторов с точным скалярным коэффициентом |
| `form(context, terms, limits=...)` / `Form` | Отображение или последовательность пар `(SimpleTerm, coefficient)`; каждое слагаемое означает коэффициент **при квадрате** структуры |

**Индексы — позиции от 0 до n−1 в `context.labels`, а не сами метки.**
Это относится и к целочисленным меткам: при `labels=(10,20)` атомы имеют
позиции 0 и 1. Внешние коэффициенты с переставленными индексами получают
ориентационный знак; повтор позиции даёт нуль.

Допустимый фактор `SimpleTerm` — другой `SimpleTerm` того же контекста либо
дескриптор `('atom', (i,))` / `('boundary', (i,j,...))`.
Удобные конструкторы:

```python
from polyform_algebra.core import Context, Atom, Boundary, Unit, simple_term

c = Context(('a', 'b', 'c'))
a = Atom(c, 0)
ab = Boundary(c, (0, 1))          # b - a
unit = Unit(c)                   # exterior 1
product = simple_term(c, (a, ab))
expanded = product.as_exterior() # data object, not Calculation
```

Компактная граница непуста, не допускает повторов и требует ε=1 для своих
вершин. Граница одной вершины равна 1. Для произвольных точных весов следует
применять `boundary` к координатному `Exterior`.

Внутри `SimpleTerm` сохраняются знаки перестановки вершин и градуированной
перестановки факторов. Его `grade` — сумма грейдов факторов. Внешний нуль
после раскрытия не имеет единственного грейда; сохранённый синтаксический
грейд нулевого `SimpleTerm` не используется как математический инвариант.

`Exterior` и `Form` поддерживают точные `+`, `-`, унарный минус, умножение
и деление на рациональный скаляр. `SimpleTerm` поддерживает унарный минус
и умножение на рациональный скаляр. Арифметика возвращает объект данных.
Для внешнего и полиформного произведений используются разные именованные функции.
`square(r*S)` учитывает множитель `r²`, тогда как `r*square(S).value` — множитель r.

`coefficients`, `factors`, `terms` сохраняются как кортежи; исходные отображения
копируются. Ненулевые рациональные коэффициенты никогда не отбрасываются
из-за размера. Разные записи одной формы могут храниться по-разному: `==`
сравнивает нормализованную запись, **математическое сравнение — `equivalent`**.

## Операции

Каждая именованная операция ниже возвращает `Calculation(value, diagnostics)`.
`diagnostics.status='exact'`; `checks` содержит применённый `max_terms`.
Конструкторы и `SimpleTerm.as_exterior()` возвращают сами объекты данных.

| ID / функция | `value` и условия |
| --- | --- |
| A01 `wedge(X,Y, *, limits=None)` | `Exterior`; билинейное внешнее произведение с ориентационными знаками |
| A02 `boundary(X, *, limits=None)` | `Exterior`; сжатие функционалом ε с чередующимися знаками, в том числе при неединичных весах |
| A03 `grade_part(X,k, *, limits=None)` | `Exterior` или `Form` того же типа; k — целое неотрицательное число |
| A04 `square(S, *, limits=None)` | `Form`; S должен быть `SimpleTerm`, а не произвольным внешним объектом |
| A05 `form_product(F,G, *, limits=None)` | `Form`; `[X]²[Y]²=[X∧Y]²`, билинейность и коммутативность |
| A06 `equivalent(F,G, *, limits=None)` | `bool`; точное сравнение всех внутренних координатных пар |
| A07 `polar_form(u,v, *, limits=None)` | `Form`; `{u,v}` без 1/2, только первый грейд либо нуль, весь базис имеет ε=1 |
| A08 `form_exp(P, *, limits=None)` | `Form`; конечная экспонента, скалярная компонента P должна быть нулевой |
| A09 `laplacian_form(net, *, limits=None)` | `Form`; сумма `c_ij square(Boundary(i,j))` точной сети, с полным контекстом вершин |
| A10 `spanning_coefficient(F, *, limits=None)` | `Fraction`; коэффициент фиксированной формы `T_n`, n≥1, ε=1, F на границах |
| A11 `potential(M,F, *, limits=None)` | `Fraction`; `tau(M F)` в общем контексте, обе формы на границах; допустимо `tau(M)=0` |
| A12 `evaluate_form(net,F, *, limits=None)` | `Fraction`; линейная метрическая оценка F на границах точной непустой связной сети |

`wedge`, `boundary`, `polar_form` принимают `Exterior` и раскрывают переданный
`SimpleTerm`. Форму вместо внешнего объекта они не принимают.
`Coordinates` автоматически во внешний объект не переводятся: необходимо
явно построить `exterior(context, {(i,): value, ...})`.

## Математические решения

**Эквивалентность.** Для `X=sum x_I e_I` внутреннее раскрытие квадрата хранит
коэффициенты `x_I x_J` всех упорядоченных пар (I,J). Сравниваются полные точные
суммы. Это проверяет скалярную и старшую компоненты, а не только пробные
произведения. Конструктора таких пар в публичном API нет: общие билинейные
формы не добавлены.

**Граничная подалгебра.** После суммирования координатных пар проверяется
нулевое сжатие ε в каждом из двух аргументов. Поэтому допускается сокращение
неграничных составляющих разных слагаемых, даже если атомарные факторы ещё
остались в хранимой записи. Проверка только названий или отдельных термов
не используется.

**Экспонента.** Каждый допустимый положительно-градуированный `SimpleTerm`
разложим в произведение векторов. Его квадрат как форма имеет нулевой квадрат
в алгебре форм. Поэтому переиспользована факторизация старого `Polyform.exp`:
`exp(sum c*q)=product(e+c*q)`, с точными коэффициентами и проверками ресурсов.
Она совпадает с рядом с факториалами, включая смешанные грейды. Ненулевые
грейды ограничены n в полной алгебре и n−1 на границах; превышение обнуляется
внешней зависимостью, а не усечением ряда. `exp(0)=e`, в том числе при n=0.
Ненулевая скалярная компонента отклоняется; прежняя численная экспонента
старого API остаётся доступной без изменения поведения.

**Остовной коэффициент.** `T_n=square(partial(a_0...a_(n−1)))` определяется
всем контекстом, включая изоляты. После проверки граничности его коэффициент
читается по диагональной паре структуры `(1,...,n−1)`, чей коэффициент в
границе равен +1. При n=1 это пустая структура и `T_1=e`. Отсутствие грейда
n−1 даёт 0; подмена текущим старшим ненулевым грейдом запрещена.

**Оценка формы.** Используются точные миноры гриниана: для координатной пары
(I,J) вычисляется `det Gr[I,J]`, для пустой пары — 1. При проверенной
граничности всего выражения это внутренняя метрика на внешних степенях W₀.
Полная экспонента не строится. В частности, оценка `[u]²[v]²` равна
`u²v²−(u·v)²`, а не произведению двух оценок. Потенциал определён и для
несвязной сети, но метрическая нормировка по нулевому глобальному τ запрещена.

## Лимиты и ошибки

`AlgebraLimits(max_terms=100000)` ограничивает размер разреженных промежуточных
выражений, число факторов и число кандидатов перед декартовым раскрытием
(например, `len(X)*len(Y)` или `len(expansion)**2`). Это консервативный
лимит: операция может быть отклонена даже при малом конечном результате,
если промежуточное раскрытие велико или слагаемые сократились бы позже.
Количество кандидатов проверяется до построения произведения; размер
накопителя — до добавления нового ненулевого ключа.

По умолчанию операция наследует меньший лимит операндов; явный `limits=`
может его изменить. При превышении возникает `ResourceLimit` с кодом
`RESOURCE_LIMIT`, параметрами `max_terms` и `requested`. Частичного результата
нет. Точные пределы времени, размера матриц и битовой длины коэффициентов
этим параметром не задаются; это отдельные ограничения будущего агента.
Лимит не обещает одинаковую стоимость разных эквивалентных записей.

Численный формальный объект, неподдерживаемая форма/поляризация или символы —
`UNSUPPORTED_OPERATION`; неграничная форма для A10–A12, пустой недопустимый
контекст, неверный грейд — `DOMAIN_ERROR`. Неверные индексы, размеры,
повторы в компактной границе и недопустимые числа — `INVALID_INPUT`.
Чужие контексты — `CONTEXT_MISMATCH`; проверка не отключается для нулей.

## Совместимость и источники

Старые `Point`, `Simplex`, `Polysimplex`, `quForm`, `Polyform` и их методы
не менялись. Переиспользованы их математические правила ориентаций,
координатного сравнения, поляризации первого грейда и факторизации экспоненты.
Новый слой отдельно обеспечивает неизменяемые контексты, ограничения грамматики,
ресурсов и строгую граничную проверку. Объединение внутренних механизмов
за совместимыми адаптерами остаётся этапом 7. NetworkX-зависимость прежнего
корневого импорта на этом этапе не перестраивалась.
