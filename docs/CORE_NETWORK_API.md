# Матрицы графа и резистивная геометрия — этап 3

Версия 0.4.0. Реализованы C02/C03, M01–M04 и G01–G04 технического задания.
Импорт: `polyform_algebra.core`. Все функции ниже возвращают `Calculation`:
полезное значение доступно как `.value`, сведения о проверке — `.diagnostics`.
Конструктор `network` по-прежнему возвращает `Network` непосредственно.

| Функция | Результат и условия |
| --- | --- |
| `network_from_laplacian(values, vertices, arithmetic="exact", policy=None)` | Проверенная сеть из симметричной L с нулевыми суммами строк. Знаки проводимостей проверяются; положительные связи не удаляются по порогу |
| `network_from_resistance(values, vertices, arithmetic="exact", policy=None)` | Сеть из R. Конечные блоки должны быть компонентами; после двойного центрирования проверяются положительность метрики и знаки обратной L |
| `laplacian(net)` | `MatrixData`: сумма проводимостей на диагонали, противоположные проводимости вне диагонали |
| `green(net)` | `MatrixData`: центрированная обратная отдельно на каждой исходной компоненте |
| `resistance(net, pairs=None)` | Полная R либо `PairValues(context, pairs, values)` в заданном порядке. Для выбранных пар полная R не строится; плотная Gr пока строится |
| `spanning_tree_weight(net, componentwise=False)` | Кофактор L либо список `(component_labels, weight)`. Глобальный ответ для несвязной/пустой сети — 0, для одной вершины — 1 |
| `inner_product(net, u, v)` | `uᵀGrv`, только для согласованных `Coordinates` с нулевой суммой в каждой компоненте |
| `gram(net, U, V=None)` | Матрица `UᵀGrV`; оси соответствуют позициям в списках векторов |
| `blade_inner_product(net, U, V)` | Определитель перекрёстной Gram-матрицы. Грейды равны; пустые списки дают 1; перестановка меняет ориентационный знак |
| `simplex_volume_squared(net, vertices)` | `det(Gram)/(k!)²` для k+1 различных вершин одной компоненты; одиночная вершина даёт 1 |

В точном режиме матрицы состоят из `Fraction`; вычисления выполняются через
точные матрицы SymPy. В численном — NumPy float64. Нельзя неявно соединить
координаты из разных контекстов, порядков вершин или режимов.

Пустые сети дают матрицы 0×0. Для изолята Gr и R равны `[0]`. Бесконечное
сопротивление между компонентами в exact обозначено `INFINITY`, в numeric —
`float("inf")`. Это допустимое значение R, а не ошибка вычисления. Явное
`to_numeric` переводит маркер в численную бесконечность. Другие матричные
представления, координаты и проводимости по-прежнему требуют конечных чисел.

`MatrixData` остаётся контейнером, а не сертификатом математической
допустимости произвольного пользовательского массива. Для восстановления
сети используйте C02/C03, которые выполняют соответствующие проверки.

## Численный режим и границы надёжности

Каждая связная компонента нормируется по собственному масштабу. Обращаются
ровно n−1 положительных мод; связность берётся из входной сети, а не из
численного ранга. Слабая связь может сделать обращение неразрешимым при
заданной точности, но не превращается в отсутствие связи.

Порог ранга: `max(rtol, 100*n*eps)`. Дополнительно проверяются обусловленность
и невязка `L_scaled * Gr_scaled − J`. `SolveCheck` содержит метки компоненты,
масштаб, ранг, оценку обусловленности и невязку. Диагностика статуса
`approximate` не является математическим доказательством точности результата.

При импорте L допустимы малые симметризация и пересборка диагонали в пределах
политики; эти изменения перечисляются в `diagnostics.corrections`.
Отрицательные проводимости не исправляются. Для R требуются симметричные
значения и нулевая диагональ; бесконечности должны отделять целые компоненты.

**Численное восстановление по R не угадывает нулевые связи.** Если знак
восстановленной проводимости неразрешим возле нуля, возвращается
`NumericalUnresolved`, даже для математически корректной разреженной сети.
Точное восстановление рациональной R работает и для отсутствующих связей.
Успешное численное восстановление дополнительно проверяется обратным расчётом R.

Слишком плохая обусловленность, переполнение и исчезновение ненулевой
метрической величины приводят к `NumericalUnresolved`. Зависимость списков
векторов в численной G03 проверяется точно для поданных двоичных float, чтобы
не объявлять просто малый объём нулевым. Квадрат нормы не исправляется через
модуль отрицательного результата.

Вычисления предназначены для небольших плотных задач. Разреженные решатели,
Дирихле/Крон в новом интерфейсе, общий формальный API и направленные метрики
относятся к следующим этапам. Старый `polyform_algebra.matrix` и классы
алгебры сохранены без изменения их контрактов.

## Пример

```python
from polyform_algebra.core import network, resistance, spanning_tree_weight

g = network(["a", "b", "c"], [("a", "b", 1), ("b", "c", 2)])
print(resistance(g, pairs=[("a", "c")]).value.values)  # (Fraction(3, 2),)
print(spanning_tree_weight(g).value)                   # 2
```

Полный пример: `python -m examples.reference_network_geometry`.
