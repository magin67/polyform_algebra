# Проверка реализации и упрощение

Дата: 2026-10-29. Проверена реализация после e9bb0f8.

## Принятое ограничение

Работа продолжается внутри существующей модели квадратичных форм. Общие билинейные формы не добавляются. Предложение такого расширения в первоначальном PMG_INTRO_AUDIT.md теперь является историческим вариантом, а не планом реализации. Ограничение закреплено в AGENTS.md.

## Исправлено в этом проходе

- `Polyform.from_pairs` суммирует повторные слагаемые вместо перезаписи. Например, веса 2 и 3 одной формы теперь дают 5.
- `extract_max_coeff`, `extract_max_coeff_all_grades`, `extract_diagonal_components` работают для Polyform: раньше передавали неподдерживаемый аргумент term_type. Теперь подклассы создают результаты через `_from_terms`, сохраняя в том числе изолированные вершины.
- Хеш Element соответствует существующему равенству по имени и аффинному весу. Равные Point и Element больше не оказываются разными ключами словаря.
- При передаче списка представлений каждому сопоставляется отдельная запись basis_for_frame; входной список копируется.

## Упрощено без расширения алгебры

- В конструкторе Polysimplex копирование объекта использует тот же цикл нормализации, что словарь и список пар.
- Повторяющееся создание результатов отбора объединено в `_from_terms` с отдельным переопределением для Polyform.
- Инициализация одного и нескольких фреймов объединена.
- Удалены перекрытые определения `_create_empty` и `Simplex.__neg__`, которые Python всё равно заменял последующим определением.
- Очистка коэффициентов выполняется одним проходом; устранено повторное обновление кэша после `_finalize`.
- Упрощена проверка единицы, удалены неиспользуемые импорт и локальная переменная.

Публичные классы и импорты сохранены. Новые пояснения и docstring написаны на английском.

## Замечания первоначального обзора (статус см. ниже)

Это не утверждение о полной корректности библиотеки. Приоритетные проблемы:

1. **Критерий эквивалентности.** `Polyform.one().is_equivalent(Polyform.zero())` возвращает True: без вершин цикл проверок пуст. Проверка только произведений с парными формами также недостаточна как общий критерий. Нужно определить область применения и сохранить поддерживаемые структурные тождества; простая замена на сравнение словарей не подходит.
2. **Контракт exp.** `Polysimplex.zero().exp()` возвращает 0, а `Polyform.one().exp()` — 2e. Это не обычная экспонента. У LinearCombination.exp отсутствует постоянный член; формула Polyform.exp как произведения (1+c·f) требует квадратно-нильпотентных слагаемых и не применима к скалярной единице. Графовые лапласианы проверены, но поддержку общего аргумента и поведение вне допустимой области следует задать явно.
3. **Изменение связанного базиса.** add_element/remove_element очищают transitions лишь с одной стороны; другой базис сохраняет устаревшую обратную матрицу. Нужна двусторонняя инвалидация и тест перехода после изменения базиса.
4. **Проверка входных данных графа.** Конструктор лапласиана проверяет не все условия матрицы сети; необходимо явно отделить допустимые сети от общих знаковых полиформ. Отдельно проверить разные типы меток и их преобразование в имена Point.
5. **Смысл to_quadratic_form.** Метод оставляет диагональные квадраты коэффициентов в ортонормированном базисе. Это не тождественно полной формальной квадратичной форме суммы. Требуется уточнение названия/контракта в рамках выбранной квадратичной модели.
6. **Служебные файлы.** pytest.ini перекрывает настройки pytest в pyproject.toml; metadata пакета дублируется в setup.py и pyproject.toml. Старый eigen_polyform.py ссылается на отсутствующие классы. Это задачи отдельной чистки конфигурации и примеров.

Следующий рекомендуемый шаг — исправить контракт и проверки is_equivalent, затем exp и инвалидацию переходов базисов. Масштабную перестройку классов до этого проводить не стоит.

## Исправления по итогам обзора — 2026-10-29

Замечания 1–3 исправлены. Замечания 4–6 остаются отдельными задачами.

- `is_equivalent` раскрывает аргумент каждой квадратичной формы в атомарные внешние произведения и сравнивает коэффициенты их квадратов. Это внутренняя проверка, а не расширение публичной алгебры билинейными объектами. Различаются ноль, единица и формы старшего грейда; сохраняется тождество четырёх вершин. Допуск абсолютный, применяется к раскрытым коэффициентам уже сохранённых объектов. Фреймы элементов автоматически не подставляются, графовый контекст не участвует в формальном равенстве. Раскрытие может быть затратным при большом числе компонент.
- `exp` отделяет скаляр c и вычисляет exp(c)·exp(N). Для полисимплекса используется конечный ряд с постоянным членом; max_terms ограничивает положительные степени N (ноль оставляет exp(c)). Для полиформы сохранено быстрое произведение факторов с проверкой квадратной нильпотентности каждого нескалярного терма. Контекст изолированных вершин сохраняется.
- Изменение состава базиса удаляет все связанные матрицы в обе стороны. Изменения без эффекта сохраняют ссылки, независимые переходы других базисов не затрагиваются. После восстановления состава можно явно вызвать link_to заново.

Источник: актуальная на дату проверки спецификация ядра PMG в ветке v5, разделы «Формальные формы», «Полиформы и произведение», «Метрическая полиформа». Алгебра остаётся ограниченной поддерживаемыми квадратичными формами.

Во всех исполняемых тестах есть английские docstring; русские комментарии и пояснения переведены (русские пути источников в URL сохранены). Удалён неисполняемый строковый блок с примерами устаревшего API из test_element.py.

## Проверка сетевых конструкторов — 2026-10-29

Пункт 4 исправлен. Пункты 5–6 остаются открытыми.

- `from_networkx` принимает только неориентированные графы без петель. Вес по умолчанию равен 1; нулевой вес не создаёт связь. Каждый вес должен быть конечным неотрицательным вещественным числом (строки, комплексные числа и логические значения отклоняются). Параллельные проводимости суммируются с проверкой переполнения.
- Сравнимые метки сохраняют прежнюю сортировку; для несравнимых типов используется порядок добавления в граф. Разные метки с одинаковым текстом получают уникальные имена точек, не конфликтующие с исходными именами. `return_points='dict'` возвращает соответствие исходных меток точкам. Некорректный режим возврата вызывает ошибку.
- `from_laplacian` проверяет двумерность, квадратность, вещественный числовой тип, конечность, симметрию, знаки диагональных и внедиагональных элементов, нулевые суммы строк. Проверки используют абсолютный допуск без относительной составляющей. Незначительная асимметрия усредняется; небольшие положительные внедиагональные элементы обнуляются. Проводимости не выше допуска пропускаются; обычное округление коэффициентов библиотеки сохраняется.
- `vertex_labels` у матричного конструктора — различные объекты `Point` с различными именами, перечисленные в порядке строк матрицы. Конструктор явно отклоняет повторения и другие типы, сохраняя существующий способ вызова с точками.
- Пустые сети, изолированные вершины и несвязные графы допустимы. Ограничения проводимостей относятся только к сетевым конструкторам: отрицательные коэффициенты, вычитание и экспоненты знаковых полиформ доступны через обычную алгебру.

## Назначение диагональной формы — 2026-10-29

Пункт 5 исправлен. Пункт 6 остаётся открытым.

Новое имя метода: `Polysimplex.to_diagonal_quform(basis, tolerance=1e-10)`. Старое `to_quadratic_form` сохранено как совместимый вызов с той же сигнатурой, без предупреждений; вычисления и проверки делегируются новому методу.

Для координат x = Σ c_i e_i метод возвращает Σ c_i² [e_i]². Это диагональная часть, а не поляризация и не полный формальный квадрат x @ x. Смешанные члены опускаются. Замена полного квадрата таким результатом допустима для оценки в метрике, обнуляющей смешанные члены в данном базисе; она не задаёт формальное тождество для произвольных алгебраических операций. `polar_form` и `scalar_product`/`@` сохраняют своё назначение: первый возвращает полярную форму без множителя 1/2, вторые — половину полярной формы для поддерживаемых аргументов первого грейда.

Метод принимает внешний ноль либо атомарные координаты первого грейда. Проверяются тип Basis, объявленный флаг is_orthonormal, атомарность и различность базисных элементов, принадлежность координат базису, допустимый допуск и конечность квадратов коэффициентов. Скалярная единица, старшие и смешанные грейды, компактные границы и уже построенные полиформы отклоняются. Границы следует заранее раскрыть, переход в нужный базис выполнить явно. Отрицательные координаты допустимы. Фреймы автоматически не подставляются.

Ортонормированность остаётся декларацией вызывающего кода: без переданной метрики метод не может проверить её численно. Базис и аргумент не изменяются. Допуск применяется к квадратам коэффициентов; стандартное округление конструктора Polyform также сохраняется.
